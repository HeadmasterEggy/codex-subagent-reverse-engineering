# Codex Subagent Reverse Engineering

Evidence-led notes on how Codex creates, coordinates, and reports subagents.

This repository contains a static-analysis report for the macOS Codex CLI embedded in ChatGPT and version-scoped comparisons with public Codex source tags. It does not include the Codex application or redistribute upstream source files.

## Current finding

The ChatGPT app embeds CLI `0.162.0-alpha.17.2`; its version-matched public source tag resolves to [`740e5af33c71225640e0c1c1555c514c2c93ab74`](https://github.com/openai/codex/tree/740e5af33c71225640e0c1c1555c514c2c93ab74). The separately installed standalone CLI reports `0.162.1` and is a different binary. The public `rust-v0.162.1` tag peels to [`092d3acd6bec3e3a14bdc7e7a2810ab628ab759d`](https://github.com/openai/codex/tree/092d3acd6bec3e3a14bdc7e7a2810ab628ab759d). Neither version match proves exact binary build provenance.

In that source snapshot, V2 spawn creates a child thread through shared `AgentControl`, persists the parent-child edge before submitting the initial input, and delivers terminal outcomes through the V2 session event path. The detached completion watcher is the legacy route. See [the evidence report](evidence/subagent-flow.md).

The targeted source diff from the embedded-version tag to standalone `rust-v0.162.1` adds the resolved model and reasoning effort to V2 `Started` activity metadata and captures startup settings before later child metadata can change. The inspected diff does not modify the V2 restore/lazy-load functions. This is a pinned source-snapshot comparison, not proof of Desktop runtime behavior; see [the version-diff finding](evidence/subagent-flow.md#standalone-cli-01621-started-activity-adds-model-metadata-2026-10-15).

The follow-up event trace confirms those fields are copied into the typed app-server subagent item, emitted on canonical `item/started` and `item/completed` notifications, and retained by history projection. Legacy `SubAgentActivity` events remain for compatibility and are not the canonical live V2 notification path. A fresh static trace of the installed Desktop bundle now shows a separate path: `thread/started` passes the thread record to the conversation store, which initializes or updates the selected child's `latestModel` and `latestReasoningEffort` from thread metadata; the panel reads those stored fields. This does not show that canonical subagent activity fields feed the panel, and no live notification payload was captured. See the [app-server event trace](evidence/subagent-flow.md#standalone-cli-01621-subagent-activity-uses-canonical-item-notifications), [installed panel metadata display](evidence/subagent-flow.md#installed-desktop-selected-child-header-displays-thread-model-metadata-2026-10-15), and [thread metadata update path](evidence/subagent-flow.md#installed-desktop-selected-child-model-settings-come-from-thread-start-metadata-2026-10-15).

Current-main source tracing also distinguishes plaintext and encrypted inter-agent message representations: plaintext delivery renders its `MESSAGE`/`NEW_TASK` envelope before creating the typed `AgentMessage`, while encrypted delivery keeps the payload opaque and stores the wake mode separately in rollout metadata. History and compaction classify agent messages as distinct boundaries, so their presence in the model input path does not guarantee every earlier message survives compaction. See the [message representation and history trace](evidence/subagent-flow.md#current-main-inter-agent-message-representation-and-history-semantics-2026-10-15).

The follow-up request trace reaches the serialization boundary: a retained message becomes a typed `agent_message` item in logical `ResponsesApiRequest.input`; HTTP serializes that request as JSON, while WebSocket may send only an incremental suffix against `previous_response_id`. Provider preparation and a narrowly scoped oversized-metadata bound can change the outgoing copy, so this source path still is not evidence of a captured or accepted live request. See the [Responses request projection trace](evidence/subagent-flow.md#current-main-agentmessage-projection-into-responses-requests-2026-10-15).

Message Board notices have a separate delivery contract: the board owns post storage, while Codex tries to inject a notice into an eligible active turn and returns `SkippedInactive` otherwise. The host does not start or restore an idle recipient for a notice. Ordinary `send_message` instead enqueues mailbox communication, with turn startup depending on its delivery mode or outstanding durable sleep. See the [message-board versus mailbox trace](evidence/subagent-flow.md#current-main-message-board-notices-are-active-turn-injections-2026-10-15).

V2 child lifetime is also distinct from caller lifetime: once `spawn` returns its acceptance receipt, caller cancellation does not retract that child. Recursive descendant shutdown belongs to the explicit `close_agent` path; natural parent completion is not evidence that its children were closed. See the [V2 child lifetime trace](evidence/subagent-flow.md#current-main-v2-child-lifetime-and-explicit-tree-close-2026-10-15).
